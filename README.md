# 机械动力整合包开服：内存和单核 CPU 别选错，新手也能把 Create 服开稳

搜「机械动力整合包开服」的人，通常已经过了"要不要开服"这个阶段，卡住的是很具体的两件事：**我这台机器够不够，以及整合包到底怎么装上去。**

先说结论性的判断：机械动力（Create）系的整合包，翻车原因很少是"CPU 核数不够"，多数是单核弱、内存给少了，或者把客户端模组一起塞进了服务端。把这三点捋顺，剩下的都是流程问题。

## 为什么机械动力整合包比普通模组服更吃配置

Create 的装置不是静态的方块实体，而是"会动的方块组装体"。传送带、机械臂、旋转轴、火车，服务端每一 tick 都要重算它们的碰撞、交互和方块更新。一个玩家搭的大型工厂，产生的 tick 压力可能比十几个挖矿的玩家还大。

这带来两个后果：

- **单核性能是硬瓶颈。** Minecraft 服务端主线程是单线程跑的，你买 8 核 3.0GHz 的机器，跑整合包大概率不如 4 核 5.0GHz。核心多只在多开服务端时有意义。
- **内存是第二瓶颈。** 200 个 mod 的整合包光加载进内存就要吃掉好几个 G，再加上玩家加载区块、实体堆积，很容量就顶到上限，然后就是 `OutOfMemoryError` 或者莫名其妙掉刻。

顺带一个容易被忽略的点：MC 版本越高越吃性能。雨云官方给的口径是 1.18+ 服务端的消耗大约是 1.16+ 的两倍，是 1.12.2 的三倍。而目前大多数机械动力整合包都停在 1.20.1 附近，正好落在高消耗区间。

## 开服要多少内存？按整合包规模对照

官方和第三方教程给出的数字不完全一致，但规律是一致的：内存跟着模组数量和装置复杂度走，不是简单跟着人数走。

| 你开的服 | 同时在线 | 最低内存 | 建议内存 |
| --- | --- | --- | --- |
| 纯 Create + 少量附属 | 1–5 人 | 4 GB | 6 GB |
| Create + 20–50 个其他模组 | 3–8 人 | 6 GB | 8 GB |
| 完整机械动力整合包（锻造边疆、航空学这类） | 3–10 人 | 8 GB | 10–12 GB |
| 大杂烩整合包顺带塞了 Create | 5–15 人 | 10 GB | 12 GB+ |

一个实操细节：**别把机器内存全部分给服务端。** 12G 的机器，服务端最大堆内存给 9–10G 比较合适，剩下 2–3G 留给系统。这条在多个整合包作者给的部署说明里都写得很明白，全给出去的结果通常是系统层面先崩。

雨云官网在游戏云页面上也标了另一组参考值，口径是"200+ mod 整合包"：

- 2核4G → 约 1 人
- 4核8G → 约 5 人
- 6核12G → 约 8 人

这组数字是长期稳定运行的保守值，不是压榨到极限的峰值。你要开的是「机械动力：锻造边疆」这类压力偏大的整合包，第三方教程给的建议是 CPU 睿频 4.0GHz 以上、内存 12–16G 起、带宽 20Mbps 左右。

## CPU 和带宽怎么挑

优先级排序很清楚：**单核频率 > 内存 > 带宽 > 核数。**

- **频率**：4.0GHz 以上是整合包服的安全线，5GHz 以上更稳。雨云游戏云的高主频机型包括 i9 14900KF、i9 14900K、Ryzen 9950X、Ryzen 7950X、Ryzen 5900X，以及性价比档的 Gold 6146、E5 2666v3。低版本整合包配 E5 或 Gold 就够，1.18+ 的整合包建议直接上高主频机型。
- **带宽**：整合包服的带宽压力来自 mod 同步和区块下发，上行 10–15M 能跑，20M 更宽裕。雨云游戏云的上行是 10M/15M/20M 三档，下行统一给到 200M。
- **防御**：雨云这些游戏云机型标的是 100G 到 200G 的高防，公网 IP 有独立和 NAT 两种。NAT 机型靠端口映射，能开 15 个端口，价格便宜不少，纯朋友联机完全够用。

## 面板服、MCSM 面板还是 VPS

雨云的游戏云有三条路线，开整合包服对应的选择逻辑不太一样。

**雨云面板**是自研面板，跑在 K8s 集群上，好处是配置能弹性升降，还能直接切换 CPU 机型（目前有 i9 14900KS 和 Platinum 8259CL 可选）。这一点对整合包服很实用——先买便宜的机型试水，机械工厂建起来卡了再切高主频机型，不用重买机器。面板支持一键开服、可视化管理、备份还原、MySQL、SFTP、网页文件管理和计划任务，也能自己改启动命令。

**关键点**：面板的一键游戏列表里没有直接对应机械动力整合包的选项，你要选**"Java 纯环境"**，然后自己上传整合包服务端。这个坑很多新手第一次开整合包服都会踩。

**MCSM 面板**是开源面板方案，一键部署支持 Java 版、基岩版、泰拉瑞亚、饥荒等，可视化管理加 SFTP 连接，和雨云面板定位接近，看个人习惯。

**游戏云 VPS** 是 KVM 云服务器，能装 Windows 或 Linux，有独立公网 IP，支持远程桌面，开放 15 个端口，可以同时开多个服务端。整合包服走 VPS 路线更自由，代价是要自己配环境、传文件。

另外雨云有几种计费模式，对开服成本影响不小：

- **固定计费**：适合天天开着的服，价格固定。
- **动态计费**：每天按前一天实际 CPU 消耗结算，闲时省钱，适合只有周末有人玩的服。
- **按日计费**：面板服专供，每天用余额结算下一天的日租。

## 开服流程：整合包特有的几个坑

流程本身不复杂，出问题的地方集中在这几步。

1. **先确认整合包的内核和 Java 版本。** 机械动力整合包绝大多数是 Forge，也有 Fabric 版本，两者不能混。Java 版本按 MC 版本走：1.18–1.20.x 用 Java 17，1.21+ 用 Java 21。版本对不上，服务端连启动都启动不了。
2. **从整合包发布页拿服务端包。** CurseForge 上要点进最新文件页面，往下拉找 Additional Files 里的服务端文件；整合包作者自己发的服务端包通常更省事。
3. **上传。** 面板服走网页文件管理或 SFTP；VPS 走远程桌面复制粘贴，文件大就挂网盘，远程桌面传大文件经常慢得让人怀疑人生。
4. **改内存。** 打开 `user_jvm_args.txt`，把 `-Xmx` 和 `-Xms` 改成机器内存减去 2–3G 的值。12G 机器就给 9G 或 10G。
5. **同意 EULA。** 第一次启动会在目录里生成 `eula.txt`，把 `eula=false` 改成 `true`，否则服务端直接拒绝启动。
6. **端口。** MC 默认 25565。NAT 机型要用控制台显示的映射端口，并且记得在 `server.properties` 里把端口改成对应的那个，这一步漏了就是"服务端正常启动但没人连得上"。
7. **正版验证。** `online-mode` 决定是否要求正版账号。全正版的朋友局保持开启更好；有离线玩家要关掉，同时记得加白名单。
8. **客户端侧模组别往服务端塞。** Flywheel 这类是客户端渲染依赖，服务端装了不一定报错，但会白白吃资源。

## 装完之后：让 Create 服别掉刻

开起来只是开始，整合包服的性能是"越住越差"的，靠这些手段维持：

- **调 Create 自身的限制。** 在 `config` 里的 Create 配置文件限制单次移动的方块数（`maxBlocksMoved`、`maxBlocksAttached`），大型可动装置是瞬时卡顿的主要来源。
- **降视距。** `view-distance` 和 `simulation-distance` 降到 6 左右，对 TPS 的提升立竿见影。
- **提前生成地形。** 用 Chunky 在没人上线的时候把主城周边预生成完，能省掉大量探索时的卡顿。
- **管住实体。** 传送带上溢出的物品、掉在地上的掉落物都是 TPS 杀手。要求所有加工线必须接收集箱，别让物品无限堆积。
- **闲置换机械用离合器关掉。** 一个一直在转的工厂，和一个能随时停的工厂，CPU 占用差很多。
- **装 Spark 看数据。** 掉刻时先看是哪个模组、哪个区块在吃 tick 时间，再针对性处理，比盲目加内存有效。

## 几个常见问题

**我和朋友 4 个人玩机械动力整合包，最低买什么？** 4核8G 的高主频机型能比较舒服地跑起来，多人长期建工厂建议直接 4核8G 起步、宁可加到 6核12G。2核4G 只能做到"能开起来"，不适合长期生存。

**固定计费还是动态计费？** 天天有人在线就选固定计费，价格可预期；只有周末开黑选动态计费更省，闲时几乎不烧钱。

**面板服能装整合包吗？** 能。选"Java 纯环境"，上传整合包服务端后改启动命令即可。面板本身还支持重装/切换游戏服务端，后期想换整合包不用重新买机器。

**服务端和客户端版本对不上怎么办？** 这是整合包作者的更新节奏问题，不是服务器的问题。等服务端包更新，或者本地用同版本客户端，别强行改版本号。

**7 天无理由退款是真的吗？** 雨云公开政策是云服务器和游戏云产品 7 天内无理由退款，每个账号限 3 次；另外支持 1 元试用一天（每款限 1 次，较贵的产品试用价会高一些，面板服见过 2 元一天的，也可以按天付）。
